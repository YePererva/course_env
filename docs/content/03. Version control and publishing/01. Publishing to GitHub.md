# Publishing to GitHub pages 

a.k.a. Mono-repository

In VSCodium you can simply initialize the Git repository. 

Interestingly enough it ignored the `env` folder. Usually, before initializing, you should create file `.gitignore` and put everything, that is not needed there. Bttert to create it now, and add there everything for python [.gitignore](https://github.com/github/gitignore/blob/main/Python.gitignore) also add there `site` folder. This is the default folder where mkdocs build the documentation. So, just add in the beginning of `.gitignore`

```
# MkDocs documentation
site*/
public*/
```

Alternatively, there is a [web-service](https://www.toptal.com/developers/gitignore/) for generating `.gitignore` files. 

At this time point, let's check push everything to the Github with VS Code. 

Now, add to your repository possibility to publish from `gh-pages` branch, as specified per [documentations](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) and to make it possible, create the CI file `.github\workflow\ci.yml`

```YAML title=".github\workflows\ci.yml"
name: ci 
on:
  push:
    branches:
      - main
permissions:
  contents: write
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Configure Git Credentials
        run: |
          git config user.name github-actions[bot]
          git config user.email 41898282+github-actions[bot]@users.noreply.github.com
      - uses: actions/setup-python@v5
        with:
          python-version: 3.x
      - run: echo "cache_id=$(date --utc '+%V')" >> $GITHUB_ENV 
      - uses: actions/cache@v4
        with:
          key: mkdocs-material-${{ env.cache_id }}
          path: .cache
          restore-keys: |
            mkdocs-material-
      - run: |
          python -m pip install --upgrade pip
          python -m pip install -r prerequisites.txt 
      - run: mkdocs gh-deploy --force
```

This example is based on [this](https://squidfunk.github.io/mkdocs-material/publishing-your-site/), with some differences:

- using the default `main` branch as is currently made by GitHub
- installing the bunch of prerequisites from the `prerequisites.txt` file

The only problem with this approach is that it you **MUST HAVE** this repository as public or have a paid subscription. Don't store any  private info in such repository.

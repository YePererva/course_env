    Preparing Minimal Working Environment¶

    Hereinafter, it is assumes that the project will be in folder D:\demoproject or, if accessing from WSL /mnt/d/demoproject

    Official documentation

    • Create the folder D:\demoproject
    • Open it with VSCodium
    • Run the terminal from it
    # Create the virtual environment with built-in module "venv"
python -m venv .\env

# activate the environment
. .\env\Scripts\Activate.ps1

# update the pip
python -m pip install --upgrade pip

# Install mkdocs-material
python -m pip install mkdocs-material

    cd /mnt/d
mkdir demoproject
cd demoproject

# venv is not part og Ubuntu WSL by default
sudo apt install python3-venv -y

# Create the virtual environment "venv" module
python3 -m venv ./env

# activate the environment
. ./env/bin/activate

# update the pip
python3 -m pip install --upgrade pip

# Install mkdocs-material
python3 -m pip install mkdocs-material

    It is all nice, but better to create the file prerequisites.txt for later use and enlist all dependencies over there. In such a case, we can install all other dependencies with one-liner 

    python -m pip install -r prerequisites.txt

    as of now, there will be only one line with mkdocs-material.

    Now, lets test if it works . From within the same terminal window type : 

    python -m mkdocs new .

    This would create the docs folder and configuration file mkdocs.yml. We can see what it created for us, via running the following command: 

    python -m mkdocs serve

    NB!: if you are running this server from another computer in the local network (per say from ProxMox container), than replace starting cmd with (or even change the port):

    python -m mkdocs serve -a 0.0.0.0:8000

    The output should be alike: 

    INFO    -  Building documentation...
INFO    -  Cleaning site directory
INFO    -  Documentation built in 0.20 seconds
INFO    -  [12:44:51] Watching paths for changes: 'docs', 'mkdocs.yml'
INFO    -  [12:44:51] Serving on http://127.0.0.1:8000/

    And we can access the freshly created web-site at the address http://127.0.0.1:8000/

    Later we can add to prerequisites:

    • mkdocs-material-extensions
    • mkdocs-include-markdown-plugin
      • for including the text of files into markdown itself
    • mkdocs-git-revision-date-plugin
      • to show the last update date/time on the page

    Now, when we made the minimal working example, let's adjust our VSCodium to be easier to work with.

    The whole configuration of the mkdocs project is going to be stored within the mkdocs.yml file. This is the YAML file, where should not make errors, and lets install syntax highilght for it into VSCodium.

    Add a few extensions for easier life:

    • YAML from RedHat, will highlight the errors in YAML files if we'll make any

    To make it work, navigate to VSCodium settings → User → Extensions → YAML. Here we can see adjustable settings, but we are looking for it's code representation.

    Than adjust it to be alike: 

    {
    "redhat.telemetry.enabled": false
    "yaml.schemas": {
        "https://squidfunk.github.io/mkdocs-material/schema.json": "mkdocs.yml"
      },
      "yaml.customTags": [
        "!ENV scalar",
        "!ENV sequence",
        "!relative scalar",
        "tag:yaml.org,2002:python/name:material.extensions.emoji.to_svg",
        "tag:yaml.org,2002:python/name:material.extensions.emoji.twemoji",
        "tag:yaml.org,2002:python/name:pymdownx.superfences.fence_code_format"
      ]
}
